# 报修模块与模块管理

## 一、背景与目标

**现状**：学生入口 `/student` 是单一的「宿舍报修」表单（校区 + 楼号 + 房间号）；管理员后台只有「校区和楼号设置」「报修工单管理」两个菜单。

**目标**：
1. 学生从入口进入后先看到报修模块列表：宿舍报修、实验室报修、食堂报修、教室报修、办公室报修……点哪个模块进哪个表单。
2. 管理员后台新增「模块管理」：勾选启用/停用、拖拽调整顺序、新增/重命名/删除模块。

**已与用户确认的三项决策**：
1. **分派方式**：非宿舍模块工单**仅管理员可见**；宿舍报修仍按校区 + 楼号分派给宿管处理。
2. **表单字段**：非宿舍模块隐藏校区/楼号/房间号，改为「具体地点」文本框。
3. **维护范围**：模块可增、删、改、启用/停用、拖拽排序。

## 三、数据模型与规则

`config.json` 新增 `modules` 数组，**数组顺序即学生入口展示顺序**（不设 order 字段）：

```json
"modules": [
  { "id": "dorm", "name": "宿舍报修", "enabled": true, "locationMode": "building" },
  { "id": "lab", "name": "实验室报修", "enabled": true, "locationMode": "custom" },
  { "id": "canteen", "name": "食堂报修", "enabled": true, "locationMode": "custom" },
  { "id": "classroom", "name": "教室报修", "enabled": true, "locationMode": "custom" },
  { "id": "office", "name": "办公室报修", "enabled": true, "locationMode": "custom" }
]
```

- `locationMode: 'building'`＝宿舍模式（校区+楼号+房间号，分派宿管）；`'custom'`＝具体地点模式（仅管理员可见）。
- 哨兵模块 `dorm`：**不可删除**（服务端 400 拦截）；`locationMode` 服务端强制归正为 `'building'`；允许停用。
- 新增模块一律 `custom`，id 由前端生成 `m-<时间戳36进制>-<4位随机>`（中文名不能当 id，重命名后 id 必须稳定）。
- 模块名唯一（前端拦截 + 服务端校验）。
- **存量工单无 `module` 字段 → 读取期一律按 `'dorm'` 处理**（`item.module || 'dorm'`），不写迁移脚本。
- 新工单结构：新增 `module`、`location` 两字段；宿舍工单 `location: ''`，非宿舍工单 `campus/building/roomNumber` 存空串、`location` 存具体地点。

### 1. 新增 [server/modules.js](file:///d:/Visual%20Studio%20Code/ChengXu/宿舍报修系统/宿舍报修系统/server/modules.js)（约 65 行）

```js
export const DORM_MODULE_ID = 'dorm';

/** 默认模块：顺序即展示顺序。修改时同步 client/src/lib/constants.js 的 defaultModules */
export const DEFAULT_MODULES = [
  { id: 'dorm', name: '宿舍报修', enabled: true, locationMode: 'building' },
  { id: 'lab', name: '实验室报修', enabled: true, locationMode: 'custom' },
  { id: 'canteen', name: '食堂报修', enabled: true, locationMode: 'custom' },
  { id: 'classroom', name: '教室报修', enabled: true, locationMode: 'custom' },
  { id: 'office', name: '办公室报修', enabled: true, locationMode: 'custom' },
];

const LOCATION_MODES = ['building', 'custom'];
const isValidModule = (item) =>
  item && typeof item === 'object' &&
  typeof item.id === 'string' && item.id.trim() &&
  typeof item.name === 'string' && item.name.trim() &&
  typeof item.enabled === 'boolean' &&
  LOCATION_MODES.includes(item.locationMode);

/** 读盘兜底：过滤非法项、按 id 去重、dorm 强制 building；缺 dorm 时在首位补默认项 */
export const normalizeModules = (raw) => { /* 见上文规则；全部非法时回退 DEFAULT_MODULES 副本 */ };

/** 写入校验：返回 { error } 或 { modules }；缺 dorm 视为「试图删除宿舍报修模块」 */
export const validateModules = (raw) => {
  if (!Array.isArray(raw) || !raw.every(isValidModule)) return { error: '报修模块配置格式不正确' };
  if (new Set(raw.map((m) => m.id.trim())).size !== raw.length) return { error: '报修模块 id 重复' };
  if (new Set(raw.map((m) => m.name.trim())).size !== raw.length) return { error: '报修模块名称重复' };
  if (!raw.some((m) => m.id.trim() === DORM_MODULE_ID)) return { error: '宿舍报修模块不可删除' };
  return { modules: raw.map((m) => ({ ...规范化，dorm 强制 building... })) };
};

export const findModule = (config, id) => (config?.modules || []).find((m) => m.id === id);
```

## 六、假设与决策

1. 三项用户确认（分派 / 表单 / 维护范围）为最终设计，不再扩展。
2. dorm 模块**可停用但不可删除**；删除模块**不删除历史工单**（卡片显示「已删除的模块」）。
3. 模块不支持独立图标、每个模块独立故障类型等未要求的扩展；故障类型沿用现有 `repairCategories`。
